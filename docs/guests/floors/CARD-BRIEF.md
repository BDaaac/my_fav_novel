# Задание: карточка гостя для этажа

Сайт — картотека героев новеллы «Побег из отеля с привидениями». У каждого гостя есть карточка на каждый этаж отеля: какой он на этом этаже, что получил, что сделал, с кем был близок. Ты пишешь **одну карточку одного гостя для одного этажа** по готовым выпискам из глав.

## Источники

Выписки сделаны читателями, которые прочли главы целиком. Для тебя они уже нарезаны:

- `docs/guests/floors/digest/<этаж>/<id>.md` — всё, что читатели выписали про твоего гостя (блоки «По героям» и блоки «[ОТНОШЕНИЯ]» с его участием), по порядку глав.
- `docs/guests/floors/digest/<этаж>/_chrono.md` — хронология этажа по главам: что за комната, какая попытка, чем кончилась. Читай целиком, чтобы понимать порядок событий и исходы попыток.
- `docs/guests/floors/digest/<этаж>/_misc.md` — новые лица, неясные места, сбои перевода. Заглядывай, когда что-то не сходится.
- Карточка первого этажа того же гостя, если она есть: `src/data/guests/<id>.json`, `src/data/guests/extra/<id>.json`, `src/data/guests/back/<id>.json`, `src/data/guests/feats/<id>.json`. Она задаёт тон и длину текста и показывает, с чем гость пришёл на этаж.

Сами главы не перечитывай. Если в выписках чего-то нет, значит, в карточке этого тоже нет.

## Что такое «этаж»

- Второй этаж — главы 151–547: номера 201–207, повторные заходы в 104-й и 203-й, арки отдыха между ними. В файле выписок 139–157 к этажу относится только то, что с главы 151.
- Карточка описывает гостя **к концу этажа**, а оборот перечисляет всё, что с ним было на этаже.

## Главные правила

1. **Только факты из выписок.** Никаких догадок, оценок мотивов и красивых обобщений. Если читатель пометил что-то как неясное, спорное или известное только с чужих слов, не выдавай это за факт: либо опусти, либо запиши в `uncertain`.
2. **Сны, иллюзии, двойники, одержимость, роли внутри комнат — не сам герой.** Роль в комнате идёт в оборот (`back.rooms[].role`). Поступки, совершённые телом героя под чужим управлением, ему не приписывай.
3. **В видимом тексте нет оговорок, номеров глав и слов «в главе», «по тексту», «вероятно», «по-видимому».** Номера глав идут только в поля `ch`.
4. **Пиши литературно и коротко, по-русски, своими словами.** Без цитат. Без канцелярита. Одно предложение — одна мысль.
5. **Отношения показывай в развитии**: что было и чем стало на этом этаже. Не «близкие подруги», а что между ними на деле произошло.
6. Противоречия перевода не выбирай наугад. Если выписки дают две версии, запиши обе в `uncertain`, а в карточку не ставь ни одну.

## Формат

Один файл строгого JSON (UTF-8, без комментариев) по пути, указанному в задании.

```json
{
  "id": "han-gain",
  "name": "Хан Гаин",
  "registry": [
    { "label": "Возраст", "value": "20 лет", "ch": [476] }
  ],
  "about": [
    { "text": "Абзац о том, каким гость стал на этом этаже.", "ch": [209, 341] }
  ],
  "blessing": {
    "name": "Мудрость",
    "patron": "Сова",
    "text": [ { "text": "Что Благословение умеет к концу этажа, какие усиления получены.", "ch": [345, 477] } ],
    "limits": [ { "text": "Ограничение, цена или наказание одной фразой.", "ch": [345] } ]
  },
  "legacies": [ { "name": "Название", "room": "104", "ch": [421], "text": "За что получено, что делает, чего стоит." } ],
  "items": [ { "name": "Название", "source": "откуда", "ch": [144], "text": "Что это и как использовалось." } ],
  "back": {
    "rooms": [ { "room": "201", "title": "Куб", "result": "Провал", "role": "агент Управления", "note": "первая попытка", "ch": [152, 156] } ],
    "deaths": [ { "room": "201", "cause": "убит гориллой", "ch": [154] } ]
  },
  "links": [ { "to": "kim-ari", "bond": "одно-два слова", "text": "Одна-две короткие фразы: что между ними на этом этаже.", "ch": [209, 479] } ],
  "merits": [ { "title": "Финальный Решатель", "room": "201", "text": "Одно предложение: что гость сделал.", "ch": [170] } ],
  "feats": {
    "best": { "title": "1–4 слова", "room": "204", "text": "Два-три предложения о главном деле гостя на этаже.", "ch": [309] },
    "more": [ { "title": "1–4 слова", "room": "205", "text": "Одно предложение.", "ch": [375] } ]
  },
  "look": {
    "summary": "Для художника: чем гость к концу этажа отличается внешне от себя на первом этаже. Только то, что остаётся с ним вне комнат.",
    "evidence": [ { "ch": [146], "text": "Что именно сказано о внешности." } ]
  },
  "uncertain": [ "Что осталось неясным или противоречивым, с номерами глав." ]
}
```

### По полям

- `registry` — 4–7 коротких граф анкеты, значение до 12 слов. Берём то, что характерно именно для этажа: возраст, если назван; уровень из таблицы уровней; кем отель делал гостя чаще всего; увечья или изменения тела, оставшиеся вне комнат; откуда пришёл в команду (для новых гостей). Граф без фактов не заводим.
- `about` — 2–3 абзаца по 2–3 предложения.
- `blessing` — состояние к концу этажа. `name` — основное название Благословения, как в Окне Статуса; усиления и способности с собственными названиями описывай в `text`. `patron` — если назван, иначе пустая строка.
- `legacies` — наследия, которые числятся за гостем к концу этажа. `items` — остальные вещи при нём. Потерянное или отданное на этом этаже упомяни в тексте той вещи или опусти.
- `back.rooms` — по одной записи на каждый заход гостя в номер на этом этаже, по порядку событий. `room` — только номер цифрами («104», «203»), повторный заход пишется тем же номером. `title` — название комнаты. `result` — строго одно из трёх слов: `Побег`, `Решение`, `Провал` — итог этой попытки, как он объявлен для группы (если гость погиб, а попытка кончилась Побегом другого, пиши `Побег`; гибель уйдёт в `deaths`). `role` — кем отель сделал гостя, 1–3 слова, или пустая строка. `note` — до 5 слов («третья попытка», «запечатан», «выжил один»), или пустая строка. Если гость в заходе не участвовал, записи нет. События вне номеров (арки отдыха, сны, вылазки наружу) сюда не идут.
- `back.deaths` — каждая смерть самого гостя на этаже: `room` цифрами (или короткое название события, если это не номер), `cause` 2–5 слов. Смерть, о которой сказано только с чужих слов без сцены, включай; смерть, про которую выписки говорят «не показано» или «неясно», не включай.
- `links` — 3–4 самых важных для гостя человека на этом этаже. `to` — id из списка ниже. Первая запись — самая важная связь. `bond` строчными буквами.
- `merits` — 0–2 записи: только то, что сам отель засчитал лично гостю (Финальный Решатель, право на наследие, особая награда). Усиления из Святилища сюда не пиши, они идут в `blessing`.
- `feats.best` — одно главное дело самого гостя на этаже (его решение, риск, умение). `feats.more` — ещё 2–4, по порядку событий. Не роль в комнате сама по себе и не то, что с гостем случилось.
- `look` — служебное поле для художника, в карточке не показывается. Пиши только то, что выписки говорят о внешности, и отделяй постоянное (осталось после выхода из комнат) от временного. Если о внешности на этаже ничего не сказано, так и напиши.
- `uncertain` — служебное, не показывается.

## В конце

Проверь, что файл — валидный JSON и что в видимых текстах нет номеров глав и оговорок. Больше ничего в проекте не меняй. В ответе напиши 5–8 строк: что вошло в карточку, что ты намеренно не включил и почему, что осталось в `uncertain`.
